# General Terms & Definitions

- <strong>open-source </strong> - is computer code made publicly available for anyone to view, use, modify, and distribute.

- <strong>cross-platform</strong> - is designed to run on multiple operating systems (like Windows, macOS, Linux, iOS, or Android) using a single, shared codebase.

- <strong>Chrome's V8 engine</strong> - is an open-source software component that executes JavaScript and WebAssembly.

- <strong>Blocking</strong> - code pauses execution until completion.

- <strong>Non-blocking</strong> - code runs tasks asynchronously without waiting.

- <strong>Synchronous & Asynchronous</strong> - refer to how tasks or communication flows are timed and executed.

- <strong>Synchronous</strong> - things happen in a step-by-step order, using a shared clock, or waiting for a reply right away.

- <strong>Asynchronous</strong> - events or tasks happen independently of the main program flow without blocking execution.

- <strong>Event-Driven Architecture (EDA)</strong> - is a software design pattern where decoupled microservices capture, communicate, and react to real-time state changes known as events.

- <strong>REST API</strong> - is an architectural style used to build web services that allow different software systems to communicate over HTTP (Representational State Transfer Application Programming Interface).

- <strong>Microservices</strong> - an architectural style in computer science where a single application is built as a collection of small, independent services.

- <strong>NPM</strong> - the default package manager and online registry for the JavaScript programming language. (Node Package Manager).

- <strong>I/O-intensive tasks</strong> - operations that spend most of their time transferring data rather than doing math.

- <strong>CPU-intensive tasks</strong> - operations that require heavy computation and processor power rather than waiting on input/output (I/O).

- <strong>I/O-bound tasks</strong> - is a process that spends most of its time waiting for input/output operations, such as network requests, disk reads/writes, or database queries, to finish rather than using the CPU.

- <strong>Runtime environment</strong> - is the software layer that provides the services, resources, and context a program needs to execute.

- <strong>Architecture in CS</strong> - the blueprint and functional design of a computer system, focusing on instruction set architecture (ISA), microarchitecture, and system design.

- <strong>Streaming</strong> - a sequence of data elements made available over time.

- <strong>Thread</strong> - the smallest sequence of programmed instructions that a operating system can manage independently.

- <strong>Main Thread</strong> - is the primary sequence of code execution in a program, responsible for starting the application, running the Main method, and managing child tasks. 

- <strong>Offload</strong> - is the process of moving heavy computing tasks from a weak device to a stronger system, such as an edge server, cloud, or secondary processor.

- <strong>Static-Typed</strong> - checks and enforces variable data types during compile-time rather than at runtime.

- <strong>Dynamic-Typed</strong> - where the interpreter assigns variables a type at runtime based on the variable's value at the time.

- <strong>Single-Threaded</strong> - is an execution approach where a program or process runs sequential code flow, utilizes one call stack, and processes one instruction at a time.

- <strong>Multi-Threaded</strong> - a programming technique where a single program runs multiple execution paths (threads) at the same time.

- <strong>REPL</strong> - is an interactive shell that allows you to execute JavaScript code line-by-line and see immediate results (Read-Eval-Print Loop).
